Build and submit a small AWS serverless feature for the homework assignment: an **Interactive Resume Visitor Board** added to the existing resume site.

The evaluator should be able to open a public S3 URL, submit a public note/question, refresh the page, and see the note loaded back from DynamoDB.

## Assignment feature

The assignment feature is the **Visitor Board**.

Required AWS service usage:

| Service | Required role |
|---|---|
| S3 | Host the existing static resume frontend files |
| Lambda Function URL | Public backend API for the visitor board |
| DynamoDB | Store and retrieve visitor messages |

Required user flow:

```text
Visitor opens S3-hosted resume site
→ visitor enters name + message
→ frontend POSTs to Lambda Function URL
→ Lambda validates and saves message to DynamoDB
→ frontend GETs messages from Lambda Function URL
→ Lambda reads from DynamoDB
→ S3-hosted page displays messages
```

## Architecture

```text
Visitor browser
    |
    | opens public S3 website URL
    v
Amazon S3 static website
    - serves resume/index.html
    - serves resume/styles.css
    - serves resume/script.js
    - serves resume/assets/
    - includes Visitor Board section
    |
    | fetch() GET /messages
    | fetch() POST /messages
    v
AWS Lambda Function URL
    - handles OPTIONS, GET, POST
    - validates name/message
    - returns CORS headers
    - writes/reads DynamoDB
    |
    | dynamodb:PutItem
    | dynamodb:Scan
    v
Amazon DynamoDB
    - table: ResumeVisitorMessages
    - stores visitor messages
```

## DynamoDB table

```text
Table name: ResumeVisitorMessages
Partition key: id
Billing mode: On-demand
```

Item shape:

```json
{
  "id": "b7f4a1c2-6d98-4e3e-9d62-67c5e5e5c123",
  "name": "Hiring Manager",
  "message": "I enjoyed reading about your cloud and AI projects.",
  "createdAt": "2026-08-06T12:00:00Z"
}
```

Validation rules:

| Field | Required | Rule |
|---|---:|---|
| `id` | yes | Generated by Lambda as UUID |
| `name` | yes | Trimmed, 1–80 characters |
| `message` | yes | Trimmed, 1–500 characters |
| `createdAt` | yes | Generated by Lambda as UTC ISO timestamp |

Read strategy:

- Use `Scan` for the MVP because the table is small.
- Scan the table, sort all returned items by `createdAt` descending in Lambda, then return the first `MAX_MESSAGES` items.
- Do **not** use DynamoDB `Scan` `Limit` before sorting if claiming to return the latest messages.

## API contract

Use one Lambda Function URL as the backend base URL. The frontend should store it in `script.js` as `VISITOR_BOARD_API`.

### `OPTIONS /messages`

Purpose: CORS preflight.

Response:

```text
204 No Content
```

Headers:

```text
Access-Control-Allow-Origin: final S3 website origin
Access-Control-Allow-Methods: GET,POST,OPTIONS
Access-Control-Allow-Headers: Content-Type
Access-Control-Max-Age: 86400
```

### `GET /messages`

Purpose: return visitor messages.

Success response:

```json
{
  "items": [
    {
      "id": "b7f4a1c2-6d98-4e3e-9d62-67c5e5e5c123",
      "name": "Hiring Manager",
      "message": "I enjoyed reading about your cloud and AI projects.",
      "createdAt": "2026-08-06T12:00:00Z"
    }
  ]
}
```

Empty response:

```json
{
  "items": []
}
```

### `POST /messages`

Purpose: create a visitor message.

Request:

```json
{
  "name": "Hiring Manager",
  "message": "I enjoyed reading about your cloud and AI projects."
}
```

Success response:

```text
201 Created
```

```json
{
  "item": {
    "id": "b7f4a1c2-6d98-4e3e-9d62-67c5e5e5c123",
    "name": "Hiring Manager",
    "message": "I enjoyed reading about your cloud and AI projects.",
    "createdAt": "2026-08-06T12:00:00Z"
  }
}
```

Validation error:

```text
400 Bad Request
```

```json
{
  "error": "Name and message are required."
}
```

Unsupported method:

```text
405 Method Not Allowed
```

```json
{
  "error": "Method not allowed."
}
```

Server error:

```text
500 Internal Server Error
```

```json
{
  "error": "Something went wrong. Please try again later."
}
```

Do not return stack traces or AWS error details to the browser. Log details to CloudWatch.

## CORS requirements

The Lambda must allow requests from the final S3 website origin.

Every response must include CORS headers, including success and error responses:

```text
Access-Control-Allow-Origin: final S3 website origin
Access-Control-Allow-Methods: GET,POST,OPTIONS
Access-Control-Allow-Headers: Content-Type
Content-Type: application/json
```

For `OPTIONS`, also include:

```text
Access-Control-Max-Age: 86400
```

Temporary `Access-Control-Allow-Origin: *` is acceptable during early testing, but the final version should use the actual S3 website origin.

## Lambda requirements

Recommended runtime: Python, because AWS Lambda includes `boto3`.

Environment variables:

| Variable | Purpose |
|---|---|
| `TABLE_NAME` | `ResumeVisitorMessages` |
| `ALLOWED_ORIGIN` | Final S3 website origin |
| `MAX_MESSAGES` | `25` |

Lambda responsibilities:

- Use one shared response helper so CORS is never missed.
- Handle `OPTIONS`.
- Handle `GET /messages`.
- Handle `POST /messages`.
- Validate required `name` and `message`.
- Generate `id` and `createdAt` server-side.
- Use DynamoDB `PutItem` and `Scan`.
- Return browser-safe errors.

## IAM requirements

Lambda execution role should include:

1. AWS managed policy `AWSLambdaBasicExecutionRole` for CloudWatch Logs.
2. One inline least-privilege DynamoDB policy allowing only these actions on the `ResumeVisitorMessages` table:

```text
dynamodb:PutItem
dynamodb:Scan
```

The inline policy resource should be only the table ARN:

```text
arn:aws:dynamodb:<region>:<account-id>:table/ResumeVisitorMessages
```

Do not use:

```text
dynamodb:*
Resource: *
```

## Build order

1. Create DynamoDB table `ResumeVisitorMessages`.
2. Create Lambda role with `AWSLambdaBasicExecutionRole` plus an inline DynamoDB policy for only `dynamodb:PutItem` and `dynamodb:Scan` on `ResumeVisitorMessages`.
3. Create Lambda function `resumeVisitorApi`.
4. Enable Lambda Function URL.
5. Test `OPTIONS`, `GET`, and `POST` directly against the Lambda URL.
6. Add Visitor Board HTML/CSS/JS to the existing resume frontend.
7. Put the Lambda Function URL into `resume/script.js` as `VISITOR_BOARD_API`.
8. Create and configure the S3 static website bucket.
9. Upload only public static files from `resume/` to S3:
   - `index.html`
   - `styles.css`
   - `script.js`
   - `assets/`
10. Update Lambda `ALLOWED_ORIGIN` to the final S3 website origin.
11. Test end-to-end from the public S3 URL.
